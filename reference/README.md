# reference/

Pointers to where information lives in external systems. Read at session start (per `../CLAUDE.md`).

## Format

```yaml
---
name: short identifier
description: one-line summary
type: reference
---

What lives where (Linear project, Drive folder, Slack channel, Airtable base, dashboard URL, etc.).

Quick facts worth surfacing inline so the look-up is fast.

**How to apply:** when to consult the external source vs the inline summary.
```

## When to add

When a recurring task or check-in needs to consult an external system. The pointer goes here once; you stop asking "where do I find X again?" every session.

## When NOT to add

- The information is already in this repo (link to the file directly instead).
- The external system is one-off (just mention it inline in the relevant doc).
